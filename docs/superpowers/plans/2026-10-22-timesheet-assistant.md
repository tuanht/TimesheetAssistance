# Timesheet Assistant Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A native macOS app that stores daily work entries locally and compiles them into plain-text timesheet lines with a local LLM.

**Architecture:** All logic (settings, rendering, scheduling, validation, prompt/parse, endpoint client, catalog) lives in a UI-free SwiftPM package `TimesheetCore`, tested with `swift test`. MLX inference lives in a second package `LocalModels` (needs `xcodebuild` because of Metal shaders). A thin SwiftUI app target generated by `xcodegen` wires them together. The model decides *how big* each task is; deterministic code lays the tasks onto the clock.

**Tech Stack:** Swift 6, SwiftUI, SwiftData, Swift Testing, `mlx-swift-lm` 3.32.3 (`MLXLLM`, `MLXLMCommon`), `xcodegen`.

**Spec:** `docs/superpowers/specs/2026-10-22-timesheet-assistant-design.md`

## Global Constraints

- macOS 15 minimum, Apple Silicon only. Not sandboxed. Entitlement: outgoing network only.
- Data, settings and model weights under `~/Library/Application Support/TimesheetAssistance/`.
- Model weights are downloaded at runtime only. Never bundle weights in the `.app` or any DMG build (user decision).
- No network calls except user-initiated Hugging Face downloads and the user's custom endpoint. No analytics, no third-party SDKs that phone home.
- Template defaults: fields in order date, start, end, description, ticket, activityType, classification; separator ` | `; date `yyyy-MM-dd`; time `HH:mm`; empty ticket `—`; separator substitute `/`; max description length off; ticket pattern `[A-Z][A-Z0-9]+-\d+`.
- Working hours defaults: 09:00–17:30, lunch 12:00–13:00, rounding 15 min.
- One entry produces its own line(s); entries are never merged.
- Activity type and classification are two independent user-editable lists. Values outside them are flagged, never accepted silently.
- Output is lines only: no header, no total, no markdown.
- Model catalog (Hugging Face repo ids, all verified to exist 2026-10-22):
  - 16 GB: `mlx-community/Qwen3-4B-4bit` (~2.5 GB), `mlx-community/Llama-3.2-3B-Instruct-4bit` (~2 GB), `mlx-community/gemma-4-e4b-it-4bit` (~3 GB)
  - 32 GB: `mlx-community/Qwen3-8B-4bit` (~5 GB), `mlx-community/Qwen3-14B-4bit` (~8 GB), `mlx-community/gemma-3-12b-it-4bit` (~7 GB)
- Commands:
  - Core tests: `swift test --package-path Packages/TimesheetCore`
  - App build: `xcodegen generate && xcodebuild -project TimesheetAssistant.xcodeproj -scheme TimesheetAssistant -destination 'platform=macOS' build`

## Review Focus

1. **Model replies with prose, code fences or `<think>…</think>` around the JSON** (Qwen3 does this). Expect the JSON to be found and parsed; if none, a readable error, never a crash. Test in Task 5.
2. **Duration hints add up to more than the working day.** Expect every entry still scheduled, overflowing lines flagged "outside working hours", nothing dropped. Test in Task 3.
3. **A meeting's stated time falls in lunch, outside hours, or overlaps another meeting.** Expect the stated slot kept and flagged, other tasks scheduled around it. Test in Task 3 and Task 4.
4. **Description contains the separator or a newline.** Expect output still one line per timesheet line. Test in Task 2.
5. **Endpoint unreachable, times out, or returns non-200.** Expect a readable error in the Compile screen and the entries untouched. Test in Task 6.

### Task 3: Duration hints and scheduler

**Files:**
- Create: `Schedule/DurationHint.swift`, `Schedule/Scheduler.swift`
- Test: `DurationHintTests.swift`, `SchedulerTests.swift`

**Interfaces:**
- Consumes: `ClockTime`, `WorkingHours`.
- Produces:
  - `enum DurationHint { static func minutes(from text: String) -> Int? }`: accepts `2h`, `~2h`, `1.5h`, `1h30m`, `1h 30`, `45m`, `45 min`, `90`; case-insensitive; else `nil`.
  - `struct ScheduleItem { entryId: UUID; hintMinutes: Int?; estimatedMinutes: Int; fixed: (start: ClockTime, end: ClockTime)? }`
  - `struct ScheduledSlot: Equatable { entryId: UUID; start: ClockTime; end: ClockTime }`
  - `enum Scheduler { static func schedule(_ items: [ScheduleItem], hours: WorkingHours) -> [ScheduledSlot] }` (sorted by start)

Algorithm (tests below do not fully pin it):
1. Free segments = `[start, lunchStart)` and `[lunchEnd, end)`; skip lunch if `lunchStart == lunchEnd`. Subtract every fixed interval.
2. Fixed items keep their stated slot exactly, even outside hours or in lunch (the validator flags them).
3. Free total `F`. Hinted flexible items get their hint minutes. Unhinted items share `F − Σhints` in proportion to `estimatedMinutes` (minimum 1). Round each to `roundingMinutes`, minimum one unit. Give the rounding remainder to the last unhinted item so the total equals `F` when it fits.
4. Lay flexible items out in input order through the free segments. When an item crosses a segment end, split it: one slot to the segment end, the rest from the next segment start (same `entryId`). After the last segment, keep going past `end` (overbooked; validator flags).

- [ ] **Step 1: Write failing tests:**
  - `DurationHintTests`: `~2h`→120, `1.5h`→90, `1h30m`→90, `45 min`→45, `90`→90, `soon`→nil.
  - `SchedulerTests.fillsDayExactlyWithNoGaps`: three unhinted items with estimates 1, 1, 2, default hours → slots cover 09:00–12:00 and 13:00–17:30 with no gap or overlap; total 450 min.
  - `biggerEstimateGetsMoreTime`: item with estimate 2 gets more minutes than estimate 1.
  - `hintIsHonouredExactly`: hinted 120 min item lasts exactly 120 min; others share the rest.
  - `fixedMeetingKeepsSlot`: fixed 10:00–10:30 kept; flexible slots avoid it.
  - `itemCrossingLunchIsSplit`: produces two slots with the same `entryId`, one ending 12:00, one starting 13:00.
  - `overbookedHintsSpillPastEnd` (Review Focus 2): hints 300 + 300 → every item present, last slot ends after 17:30, nothing dropped.
  - `fixedMeetingInLunchIsKept` (Review Focus 3): fixed 12:15–12:45 returned unchanged.
  - `allSlotsOnRoundingGrid` when no fixed items are off-grid.
- [ ] **Step 2:** Run core tests. Expected: FAIL.
